# 0009: Follow-ups from plans 0003 to 0008

- Status: In progress
- Date: 2026-10-29

## Background

Plans 0003 to 0008 are done, but their reviews left low-severity findings in each task's review notes. They are not tracked anywhere else. This plan triages them: each one is either scheduled as a task below or listed under "Not scheduled" with a reason.

A test conversion of a real draft also found that directions are dropped with newer ElevenLabs models. Two checks were also never run. Every test uses the mock provider, so the ElevenLabs adapter has never made a real call. The phone checklist has not been run on a real phone either. Plan 0005 gives it to the coordinator, but only the human has the phone.

All tasks here start after plan 0005's last task, "Paid confirm carries the approved cost", is merged, because it also owns `apps/server/` and `apps/web/`.

## Goals / Non-goals

Goals:

- Fix the follow-ups that can produce a wrong result, a confusing message, or a file written in the wrong place.
- Run the ElevenLabs adapter once against the real API, behind a decision gate.
- Have the human run the phone checklist.

Non-goals:

- New features.
- Changes to the scenario format or any other file format.

## Design

Tasks are grouped by Ownership so that the groups can run in parallel. Tasks that share `apps/cli/` run one after another.

### Already done

These follow-ups were fixed after their review notes were written:

- Plan 0006: README describes the `vd` commands.
- Plan 0007: `AGENTS.md` and the scenario guide describe `vd library promote`, `status`, and `sync`, and the guide's "Not everything is built yet" note is gone.
- Plan 0007: provider records in `credits.json` (its own task).

### Not scheduled

These follow-ups are closed without a change:

- Plan 0003: the `voice.settings` walk is recursive and copies its path at every node. YAML input cannot be deep enough for this to matter.
- Plan 0006: `-safe 1` is the concat demuxer's default, and the list holds only generated names. The libx264 `medium` preset stays until someone finds a render too slow.
- Plan 0007: library copies are not fsynced. A crash can lose only a copy that `vd generate` or `vd library sync` makes again.
- Plan 0005: the built UI is found only from a repository checkout. vd is run from a checkout until it is packaged.
- Plan 0007: provider records are never removed, and only `vd generate` refreshes provider terms. A stale record can only credit a provider that is no longer used, and the license check still runs on the newest terms after the next generate.
